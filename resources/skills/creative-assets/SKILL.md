# 创作资产管理技能

本技能面向创作团队，指导如何把一部戏的素材资产按故事时间树组织成可维护的工作目录。
时间树是从故事里抽取的时间线索引，不是剧本创作；本技能只负责「资产怎么管、目录怎么摆」。

**职责边界**：本技能管创作侧的资产与目录（命名、归属、布局、改版、移交）。
网络调研、建世界、跑仿真、导出事件请用 `narrative-sim` 技能，两者不要混用。

## 1. 资产从哪来

| 来源 | 入库口径 |
|---|---|
| 调研管线产出 | 已有 `asset_id` 与 provenance，直接进全局资产区 |
| 手工新建 | 创作团队自建，按第 2 节分配 `asset_id`，来源标注「手工」，不得伪造 provenance |
| 外部素材 | 保留原始出处链接；无出处者标 `unverified`，不冒充史实 |

没有可信来源的人物年龄、家庭、摊位等，一律当私设并显式标记，不写成史实。

## 2. 资产怎么编号

- 格式：`char_` / `scene_` / `prop_` + 名称 hash，字符集 `[a-z0-9_]`，与项目契约一致。
- 一个资产全项目唯一编号；改名不改 `asset_id`，`asset_id` 是稳定键。
- 未接入时间树时：按场景/角色手工分组，编号规则不变，待树就绪再补挂节点。

## 3. 资产归属（first_seen_node）

- 资产本体**全局唯一**，用 `first_seen_node` 记录它首次登场的节点。
- 资产是「首次在该节点登场」，不是「该节点造出来的」——它归属整部戏，不归某个节点。
- 后续节点复用时，只在自己的 `node.json` 里加引用，**不改** `first_seen_node`。
- 派生物（裁切图、选中的参考图、分镜草稿）没有独立身份，留节点目录，不分配 `asset_id`。
- 游离资产（通用道具、尚未挂节点的概念）`first_seen_node` 留空，全局存放，用到时补挂。

绝不要把资产本体复制进多个节点目录——多份副本会让改版和复用都变成跨目录同步。

## 4. 物理布局（工作目录与命名）

```text
<项目根>/
├── 00_时间树/
│   ├── T001.json                 # 时间树存档
│   └── T001-自查.md              # 自查报告，供追溯
├── 01_节点/
│   ├── N0001_午后_临安酒楼/
│   │   ├── node.json            # {node_id, source_span, asset_ids:[...]}
│   │   ├── 原文.md              # source_span 对应的原文片段
│   │   └── 派生/                # 裁切图、草稿等无 asset_id 的派生物
│   ├── N0002_顺位_二楼等候/
│   └── ...
├── 02_角色/<asset_id>/
├── 03_场景/<asset_id>/
├── 04_道具/<asset_id>/
└── 90_移交包/<world_id>/
```

**三条铁律**（违反会破坏跨节点一致性）：

1. **`node_id` 是稳定键**——节点目录可读后缀可改，`node_id` 与 `node.json` 里的值不可变。
2. **`ord` 全项目唯一**——节点按 `ord` 排序，`N{ord:04d}` 前缀不得重复。
3. **资产本体只引用不复制**——节点目录只放 `node.json` 的 `asset_id` 清单和派生物，资产本体在全局资产区。

**节点目录命名**：`N{ord:04d}_{text_time或顺位}_{地点或事件短名}`

- `text_time` 为空时用「顺位」；含非法文件名字符 `/\:*?"<>|` 时替换为安全字符；后缀限 24 字。
- 例：`N0003_三日后清晨_城门分手`、`N0002_顺位_二楼等候`。
- 重命名可读后缀不影响映射——权威映射记在 `node.json`，不在目录名里。

创建目录的操作：先读 `node.json` 取 `ord` 和 `text_time`，按上式生成目录名，建目录，
写回 `node.json` 的 `asset_ids` 引用，再把派生物放进 `派生/`。资产本体不搬进节点目录。

## 5. 改版与重拍

- 资产改版后，`first_seen_node` 与所有引用它的节点都需重新复核视觉一致性。
- 通过 `node.json` 的 `asset_ids` 反查受影响的节点：`asset_id → [node_id...]`。
- 改 `asset_id` 等于换资产，必须显式处理，不做静默替换。
- 重拍产生的事件按 `node_id` 归档到对应节点，保留新旧版本可 diff。

## 6. 移交

- 移交包用项目既有的 `export_handoff` 导出，结构为 `<world_id>/` 下 `assets/` + 引用事件 + manifest。
- 移交包根的 `WORKDIR.md` 是本规范「物理布局 + 归属」两节的副本，随数据交付，下游无需先 init。
- 密级：`persona_spec.secret` 创作可见、仿真角色不可见；移交时勿回灌角色视野。
- 创作结果人工复核后方可用于正式产出——仿真事件的复核约束不因本技能豁免。
