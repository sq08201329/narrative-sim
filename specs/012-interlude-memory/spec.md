# Feature Specification: 幕间记忆传递

**Feature Branch**: `012-interlude-memory`

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "幕间记忆传递：上一幕的事件摘要/快照注入下一幕角色初始记忆（多幕连续性）。"

## 背景与动机

一幕 = 一个世界（world_id）。目前每幕独立起跑：角色对新幕一无所知——
上一幕里结下的仇、听到的秘密、达成的约定全部蒸发。多幕剧情的连续性
（人物关系的演进、伏笔的回收）因此断裂。

本特性让上一幕的**已发生事件**以记忆形式注入下一幕角色的初始认知。
关键约束是信息不对称：角色只应记得他**当时能感知到**的事（在场听到的
对话、亲历的动作），而不是全知视角的整本流水账——否则会泄露他人私语
与暗线，破坏仿真立身之本（006 的 hidden_properties/perception 原则）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按角色过滤的上一幕记忆注入 (Priority: P1)

从上一幕 run 的事件流出发，为每个角色生成"他亲历/可感知"的记忆摘要，
并在下一幕起跑时注入其初始认知。下一幕中角色的思考与言行能体现这些
记忆（如记得某人说过的话、自己做过的事）。

**Why this priority**: 这是多幕连续性的核心机制，其余一切（审计、修订）
都建立在它之上。

**Independent Test**: 用预置两幕数据（一幕含公开对话与定向私语），生成
记忆并起跑下一幕；核验角色 A 的记忆含公开事件与发给他的私语、不含
他人之间的私语。

**Acceptance Scenarios**:

1. **Given** 上一幕 run 含公开对话与定向私语（whisper/target_only），
   **When** 生成角色记忆，**Then** 角色记忆只含他可感知的事件——
   他人之间的私语零泄漏（可逐条断言）。
2. **Given** 记忆已生成，**When** 下一幕起跑，**Then** 角色初始认知中
   可见该记忆内容（在传入角色后端/引擎的初始材料中可验证）。
3. **Given** 不传上一幕（首幕或不启用），**When** 起跑，**Then** 行为与
   现状完全一致（向后兼容锚点）。

---

### User Story 2 - 记忆可审计、可修订 (Priority: P2)

生成的每份角色记忆落库（来源 run、角色、过滤后的事件引用、摘要文本），
创作队可读取核对；如需调整（如删改某条记忆），经 011 的修订机制留痕。

**Why this priority**: 调研/仿真链路的立身之本是可对照可审计；记忆是
注入下一幕的"原料"，必须与原料同等级对待。依赖 P1 存在记忆实体。

**Independent Test**: 生成记忆后经读接口取出，字段齐全；修订后下一幕
使用修订版。

**Acceptance Scenarios**:

1. **Given** 记忆已生成，**When** 读取，**Then** 返回角色、来源 run、
   事件引用列表、摘要文本、生成方式（模型/模板）与用量。
2. **Given** 同一对（上一幕 run，角色）重复生成，**When** 再次发起，
   **Then** 默认复用已落库摘要，不重复计费（显式重生成除外）。
3. **Given** 创作队修订了某角色记忆，**When** 下一幕起跑，**Then**
   注入的是修订版（沿用 011 版号锚点语义）。

---

### User Story 3 - 摘要生成的双通道与成本控制 (Priority: P3)

记忆摘要支持真实模型生成（质量优先）与确定性模板生成（离线/零成本）
两路；真实通道有长度预算与调用上限。

**Why this priority**: 宪章 IV（Mock 基线）与 VI（成本边界）的合规性
要求；P1 用模板通道即可跑通全流程，真实通道是质量增强。

**Independent Test**: 离线模板通道生成确定性摘要（可重复断言）；真实
通道单独标记验收。

**Acceptance Scenarios**:

1. **Given** 离线环境无密钥，**When** 生成记忆，**Then** 模板通道产出
   结构化摘要（角色视角的事件转写），测试可重复。
2. **Given** 真实通道，**When** 事件数超预算，**Then** 按既定截断策略
   取舍（新近优先），单次调用输入不超预算。
3. **Given** 摘要服务失败，**When** 生成中断，**Then** 明确报错且不落
   半成品；已落库的好摘要不受影响。

---

### Edge Cases

- 上一幕 run 无任何事件：记忆为空集，下一幕正常起跑（显式标注空记忆）。
- 角色在上一幕不在场（中途加入/未参与）：该角色记忆为空或仅含其可感知
  部分；新角色无记忆。
- 上一幕有多个 run（重拍并存）：必须显式指定来源 run，不默认猜测。
- 记忆注入后角色卡本身也被修订：两者独立（卡是长期设定，记忆是上一幕
  经历），注入时二者都生效。
- 跨戏（不同资产集）引用上一幕：拒绝并明确报错（记忆不跨戏移植）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 能从指定 run 的事件流，按角色生成可感知记忆集：
  过滤口径 = 事件可见性（在场公开事件 + 定向该角色的事件），与引擎
  感知规则同语义。
- **FR-002**: 记忆生成 MUST 支持双通道：真实模型摘要（默认）与确定性
  模板摘要（离线基线）；通道显式可选。
- **FR-003**: 每份角色记忆 MUST 落库：来源 run_id、角色 asset_id、事件
  引用列表、摘要文本、生成通道、token 用量、修订版号（011 机制复用
  或同口径）。
- **FR-004**: 下一幕起跑 MUST 支持注入已落库记忆（来源 run 显式指定）；
  不指定时行为与现状一致。
- **FR-005**: 同一（run_id, asset_id）记忆 MUST 幂等复用：已存在即命中
  返回，不重复生成计费；显式 regenerate 才覆盖（覆盖走修订留痕）。
- **FR-006**: 真实通道 MUST 有输入预算（事件条数/字符上限，新近优先
  截断）与成本计量（沿 update_run_cost 口径）。
- **FR-007**: MCP 新增工具暴露：生成记忆（generate_interlude_memory）、
  读取记忆（get_interlude_memory）；create_world/run_simulation 或
  reshoot 增加来源 run 参数（memory_from）。
- **FR-008**: 记忆注入 MUST 同时覆盖两路认知载体：引擎侧角色初始材料
  与角色后端侧初始记忆——两路各自可验证。
- **FR-009**: 记忆 MUST NOT 跨戏移植：来源 run 的角色集与目标世界角色集
  不一致时，只为交集角色生成/注入，并在响应中标注差异。
- **FR-010**: 离线测试零外部调用（模板通道 + mock 接缝）；既有测试
  无回归。

### Key Entities

- **幕间记忆（interlude_memory）**: (run_id, asset_id) 唯一；事件引用、
  摘要文本、通道、用量、版号。
- **可见性过滤口径**: 事件 scope/在场信息 → 角色可感知事件子集
  （与 006 感知规则同语义）。
- **注入点**: 下一幕建世界/起跑时的角色初始材料（引擎侧 + 后端侧）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 离线测试中私语泄漏率为 0——角色记忆只含其可感知事件
  （逐条断言，含 target_only/whisper 场景）。
- **SC-002**: 真机两幕连跑：下一幕角色产出中可核验地引用上一幕经历
  （人工核对至少 1 处）。
- **SC-003**: 重复生成同一（run, 角色）记忆零重复计费（第二次走缓存，
  用量为 0）。
- **SC-004**: 离线测试全绿零外部调用；既有 169 项无回归；不启用记忆时
  行为逐键一致（兼容锚点测试）。
- **SC-005**: 记忆经 MCP 可读可审，字段完整率 100%（来源/引用/通道/
  用量/版号）。

## Assumptions

- 记忆注入的具体落点（引擎角色卡字段 vs 后端初始刺激）属实现细节，
  plan 阶段经源码实读确定。
- 摘要语言与戏一致（中文）；模板通道格式为结构化条目罗列。
- 上一幕事件量当前为十级，预算截断策略从简（新近优先）；大规模
  压缩（分层摘要）不在本期。
- 多 run 并存时来源 run 必须显式指定（不重拍场景不需要本特性）。
- 记忆内容属创作可见素材，移交包是否包含记忆留待后续（本期不做）。
