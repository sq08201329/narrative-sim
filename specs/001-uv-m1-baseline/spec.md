## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从零到「验收通过」 (Priority: P1)

开发者克隆仓库后，按 README 三步（安装依赖 → 准备环境变量模板 → 运行最小链路脚本），
在无网络、无任何 API 密钥的情况下得到脚本输出的「验收通过」，并在导出目录看到一份
逐行合法的事件流文件。

**Why this priority**: 这是整个项目的回归基线。宪章原则 IV 规定任何后续改动后本链路
不得回归；基线不存在，后续所有里程碑（真后端、调研管线、WorldSeed、MCP）都没有护栏。

**Independent Test**: 在干净检出（无虚拟环境、无数据库文件）中按 README 执行，
脚本能独立跑通并输出「验收通过」，即交付了完整的 MVP 价值。

**Acceptance Scenarios**:

1. **Given** 干净检出（无虚拟环境、无数据库文件），**When** 按 README 执行三步，
   **Then** 最小链路脚本输出「验收通过」且导出目录生成事件流文件
2. **Given** 数据库文件已存在，**When** 再次运行最小链路脚本，
   **Then** 建表幂等不报错，链路仍可完成验收
3. **Given** 同一输入参数，**When** 连续运行最小链路两次，
   **Then** 产出的事件序列完全一致（允许时间戳字段不同）

---

### User Story 2 - 契约守卫 (Priority: P2)

开发者（或后续里程碑的调研管线）试图把不符合契约的数据写入存储或导出时，
系统明确拒绝并指出不合规之处，非法数据永远不进入库或导出文件。

**Why this priority**: 契约是模块间唯一接缝（宪章原则 I）。校验缺口一旦出现，
下游视频管线会静默消费坏数据，问题到很晚期才暴露。

**Independent Test**: 直接向存储接口提交一份缺必填字段的资产或事件，观察被明确拒绝；
不依赖最小链路是否可运行。

**Acceptance Scenarios**:

1. **Given** 一份缺少必填字段的资产数据，**When** 调用入库接口，
   **Then** 被拒绝并返回指明缺失字段的错误，数据库无变化
2. **Given** 一份字段全部合法但资产 ID 格式不符约定的数据，**When** 调用入库接口，
   **Then** 同样被拒绝
3. **Given** 一条类型非法的事件，**When** 写入事件，
   **Then** 被拒绝且不写入

---

### User Story 3 - 后续里程碑的接缝就位 (Priority: P3)

后续里程碑开发者可以在不改动本特性代码的前提下：替换角色后端实现（Mock → 真实后端）、
通过唯一存储接口读写、复用事件导出逻辑。

**Why this priority**: 接缝先行能防止后续里程碑各写各的胶水，违反宪章原则 II/III。
本特性只需保证接缝存在且被最小链路真实使用。

**Independent Test**: 检查角色后端以可替换接口形态被最小链路依赖注入；
新增一个替代实现仅需改注入参数即可被链路使用。

**Acceptance Scenarios**:

1. **Given** 最小链路脚本，**When** 仅替换角色后端的注入参数，
   **Then** 链路结构其余部分零改动即可运行
2. **Given** 任意新模块需要读写数据库，**When** 检查其代码，
   **Then** 只能通过唯一存储接口完成，不存在第二条数据库通路

---

### Edge Cases

- 数据库文件已存在且含数据时重跑最小链路：建表幂等，不破坏既有数据
- 使用已存在的运行标识重复仿真：行为必须明确（拒绝或报错），不得产生排序混乱的事件
- 对一个没有任何事件的运行执行导出：产出空文件而非报错崩溃
- 环境变量模板缺失或密钥未填写：最小链路照常运行（Mock 不依赖密钥）；
  涉及真实 LLM 的模块在缺失密钥时给出明确错误而非隐晦异常

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目依赖 MUST 由 uv 创建与管理：`pyproject.toml` 声明依赖、
  `uv.lock` 锁定，两者均入库；Python 版本在 `requires-python` 中声明（宪章原则 V）
- **FR-002**: 干净检出环境下，依赖安装 MUST 一条命令完成，且全过程可复现
- **FR-003**: 系统 MUST 提供资产契约与事件契约两份数据契约定义，作为全部
  入库与导出数据的唯一校验依据（宪章原则 I）
- **FR-004**: 系统 MUST 提供数据库初始化入口，幂等创建四类存储
  （资产 / 世界 / 运行 / 事件日志）；重复执行不报错、不破坏既有数据（宪章原则 III）
- **FR-005**: 数据库读写 MUST 只经唯一存储接口；其他模块 MUST NOT 直接访问数据库
  （宪章原则 III）
- **FR-006**: 入库与导出前 MUST 执行契约校验；不合格数据 MUST 被拒绝并返回
  指明不合规之处的错误，MUST NOT 降级放行（宪章原则 I）
- **FR-007**: 系统 MUST 提供可替换的角色后端接口及一个确定性 Mock 实现：
  无需外部服务、无需密钥、同一输入重复运行产出一致（宪章原则 IV）
- **FR-008**: 最小链路脚本 MUST 依次完成：初始化数据库 → 入库示例角色与场景资产 →
  4 回合仿真 → 导出事件流文件 → 逐条复验契约 → 输出「验收通过」
- **FR-009**: 事件流 MUST 每行一个事件、可按「运行 → 回合 → 回合内序号」排序；
  事件 MUST 只引用资产 ID，MUST NOT 内联外貌文本（宪章原则 I）
- **FR-010**: 最小链路 MUST 全程离线运行，不依赖任何 API 密钥或外部服务
- **FR-011**: 系统 MUST 提供环境变量模板文件；真实密钥文件 MUST 被版本控制忽略
  （宪章原则 VI）
- **FR-012**: 链路运行结束 MUST 产出导出文件；该文件 MUST 可被下游在无数据库
  访问的条件下逐行解析消费
- **FR-013**: 实现 MUST NOT 照搬 `mydocs/` 手册附录中的代码；手册仅作架构与
  字段口径参考

### Key Entities *(include if feature involves data)*

- **资产（Asset）**: 角色 / 道具 / 场景 / 时代四类；全局唯一 `asset_id`；
  角色必须包含外貌与人格设定（年龄、职业、性格、信念、语言风格）、
  历史背景与来源、参考图、溯源信息、状态
- **事件（Event）**: 仿真产出的最小剧情单元；含运行标识、回合、回合内序号、
  类型（对话 / 动作 / 场景切换 / 旁白 / 内心独白）、角色资产 ID 引用、
  场景资产 ID 引用、因果引用、镜头提示骨架
- **运行（Run）**: 一次仿真运行的记录；关联世界、状态、token 成本累计
- **世界（World）**: 世界配置与每回合状态快照，是断点续跑的基础

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 干净检出环境下，开发者在 3 条命令、5 分钟内从零到达「验收通过」，
  全程无人工干预
- **SC-002**: 最小链路 100% 确定：同一输入重复运行产出相同事件序列
  （允许时间戳字段差异）
- **SC-003**: 链路产出事件 100% 通过契约校验；注入的非法数据 100% 被明确拒绝
- **SC-004**: 最小链路全程无需网络与任何外部服务密钥
- **SC-005**: 后续里程碑所需的三处接缝（角色后端接口、唯一存储入口、事件导出）
  全部存在且被最小链路真实调用覆盖

## Assumptions

- 执行环境已安装 uv（uv 可自行管理 Python 3.12）；操作系统为 Windows，
  开发命令以 PowerShell / Git Bash 可执行为准
- M1 使用 Mock 角色后端，不接 TinyTroupe / 真实 LLM；真后端属后续里程碑（手册 M2）
- 两张数据契约以手册 3.1 / 3.2 节的字段口径为准**重新编写**（手册未附完整 JSON 文本）
- `mydocs/叙事仿真系统开发手册.md` 附录中的代码仅作逻辑参考，不落盘照抄
- 本特性不含：真实 LLM 调用、调研管线、WorldSeed、MCP Server、视频导出展开模式
- 本地已下载的开源项目副本（见 `mydocs/opensource_repos_dir.md`）本特性不使用，
  供后续里程碑参考
