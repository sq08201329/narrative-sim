# Feature Specification: DM 裁判启用（真实裁决提供者）

**Feature Branch**: `010-dm-adjudicator`

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "启用 DM 裁判：实现真实的 DMProvider 替换 mock，让角色动作有成败与后果，世界有反作用力；调研史料注入裁决知识。"

## 背景与动机

当前仿真引擎（006 特性接入）中，角色提交的每个动作都由占位裁决器处理，一律判为
"动作顺利成功"，世界状态不产生任何真实变化。这导致仿真沦为"过家家"：没有成败、
没有后果、没有环境反作用力，涌现剧情无从谈起。

引擎本身已定义完整的裁决契约：裁决者接收全知视角上下文（世界状态、最近事件、
场景描述、裁决提示、领域知识），返回叙事结果和受白名单约束的状态效果；引擎负责
校验效果合法性（操作符白名单、数量上限）并在非法时携带错误反馈重试。本特性提供
一个真实的裁决者实现，替换占位实现，并可选用已调研入库的史料约束裁决逻辑。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 角色动作获得真实裁决 (Priority: P1)

仿真运行中，角色提交一个有风险的动作（例如"凑近偷听两名察子的谈话"），裁决者
根据世界状态与场景上下文判定结果：可能成功（获得情报），也可能失败（被察觉、
暴露状态写入世界）。裁决结果以事件形式进入事件流，后续角色能感知到后果。

**Why this priority**: 这是本特性的核心价值——让世界对动作产生真实反作用力，
是涌现剧情与"过家家"的分水岭。没有它，其余一切都无意义。

**Independent Test**: 配置一个含风险动作的仿真场景，以真实裁决者运行若干 tick，
检查事件流中存在裁决叙事事件，且世界状态快照中出现裁决产生的效果变更。

**Acceptance Scenarios**:

1. **Given** 仿真世界配置了真实裁决者且场景声明了裁决提示，**When** 角色提交
   一个动作，**Then** 事件流中出现该动作的裁决叙事事件，且叙事只描述行动者与
   世界、不替其他角色演戏。
2. **Given** 裁决者返回了状态效果，**When** 效果通过引擎合法性校验（操作符在
   白名单内、数量不超上限），**Then** 效果被应用到世界状态，后续快照可见变更。
3. **Given** 裁决者返回了越界效果（操作符不在白名单或数量超限），**When** 引擎
   校验拒绝，**Then** 裁决者收到错误反馈并重新裁决，最终产出合法结果或进入
   降级路径。
4. **Given** 一个本来会被占位实现一律判成功的动作，**When** 真实裁决者判定其
   失败，**Then** 事件流与世界状态体现失败后果（如暴露、惊动目标）。

---

### User Story 2 - 史料约束裁决 (Priority: P2)

同一题材已调研入库的史料（如"南宋皇城司的侦缉手段"）可作为裁决者的领域知识
注入，使裁决符合历史逻辑：判"偷听是否被发现"时参照史料中的侦缉能力，而不是
凭空想象。

**Why this priority**: 这是调研管线（004/005/009）与仿真引擎（006）的串连线，
让调研成果直接约束仿真，提升产出素材的史料一致性。但它依赖 P1 的裁决者先
存在，故为 P2。

**Independent Test**: 预置一条与场景相关的调研原料，启用史料注入后运行仿真，
检查裁决者收到的上下文中包含该史料要点，且裁决叙事与其一致。

**Acceptance Scenarios**:

1. **Given** 某世界关联的戏已有入库调研原料，**When** 启用史料注入并运行仿真，
   **Then** 裁决上下文的领域知识字段包含相关史料要点。
2. **Given** 没有任何相关调研原料，**When** 运行仿真，**Then** 裁决正常进行，
   领域知识为空，不因缺料而失败。
3. **Given** 史料与角色动作直接冲突（如动作违反了史料描述的律令），**When**
   裁决发生，**Then** 裁决叙事体现该约束（如动作被制止或招致缉拿）。

---

### User Story 3 - 离线开发与故障降级 (Priority: P3)

离线开发、契约测试与 CI 不依赖外部大模型：占位裁决者仍是默认基线，全部既有
离线测试不受影响。真实裁决者调用外部服务失败（超时、限流、解析失败）时，引擎
按既有重试/降级逻辑处理，仿真不崩溃、不中断。

**Why this priority**: 宪章要求适配器隔离与 Mock 基线；这是合规性需求而非新
能力，故为 P3。

**Independent Test**: 不配置任何外部密钥运行全部离线测试，全绿；以故障注入
方式模拟裁决服务连续失败，仿真 run 正常结束并留下失败事件记录。

**Acceptance Scenarios**:

1. **Given** 未配置真实裁决者，**When** 运行仿真，**Then** 行为与启用本特性前
   完全一致（占位裁决）。
2. **Given** 真实裁决服务连续不可达，**When** 引擎重试耗尽，**Then** 该动作走
   降级路径，事件流记录裁决失败，仿真 run 继续而非崩溃。
3. **Given** 真实裁决者配置启用，**When** 运行离线测试套件，**Then** 离线测试
   不发起任何真实外部调用。

---

### Edge Cases

- 裁决者返回的叙事为空或只返回效果不返回叙事：引擎按契约兜底，不产生空叙事事件。
- 裁决响应格式损坏（无法解析出叙事/效果）：视为裁决失败，走重试与降级路径。
- 同一 tick 多个角色动作均需裁决：逐一裁决，互不影响；单个失败不波及其他动作。
- 史料注入内容过长：需在预算内截断取舍，不得挤占世界状态等核心上下文。
- 裁决者判定"无事发生"（叙事存在、零效果）：合法结果，世界状态不变。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供真实裁决者实现，满足引擎裁决契约（输入全知上下文，
  输出叙事 + 状态效果），替换占位裁决者后可驱动完整仿真。
- **FR-002**: 真实裁决者 MUST 通过项目既有的统一模型出口调用大模型服务，不引入
  第二条模型调用通道（密钥与成本边界遵守宪章 VI）。
- **FR-003**: 裁决者的启用 MUST 为显式配置（场景/世界级），未配置时保持占位
  裁决行为，向后兼容既有 run 与演示数据库。
- **FR-004**: 裁决产出的状态效果 MUST 完全交由引擎既有的白名单与数量上限校验，
  裁决者自身不绕过、不扩权。
- **FR-005**: 裁决失败（服务不可达、响应损坏、效果连续非法）MUST 走引擎既有
  重试与降级路径，并在事件流中留下可审计记录，仿真 run 不中断。
- **FR-006**: 系统 MUST 支持将本戏已入库的调研原料要点注入裁决上下文的领域
  知识字段；注入为可选开关，无原料时静默缺省。
- **FR-007**: 史料注入 MUST 做长度预算控制，超出预算时截断，且不挤占裁决契约
  要求的核心上下文（世界状态、最近事件、场景描述、裁决提示）。
- **FR-008**: 裁决者的提示词 MUST 约束叙事只描述行动者与世界，禁止替其他角色
  生成言行（契约要求，防串戏）。
- **FR-009**: 裁决调用 MUST 记录可审计信息（耗时、成败、效果数、token 用量），
  沿用引擎既有的裁决调用审计口径。
- **FR-010**: 离线测试基线 MUST 保持全绿且不发起真实外部调用；真实裁决者的
  真机验收单独标记（real），不进默认测试集。

### Key Entities

- **裁决上下文（DMContext）**: 引擎组装的全知输入——待裁决动作、世界状态文本、
  最近事件、场景描述、裁决提示、允许操作符、效果上限、领域知识、目标历史、
  错误反馈、语言。
- **裁决响应（DMResponse）**: 裁决输出——叙事文本、效果列表、token 用量。
- **裁决配置（DMConfig）**: 场景级声明——裁决提示、允许操作符白名单、效果数量
  上限、事件可见范围。
- **调研原料（research_materials，既有）**: 009 特性入库的史料原文与摘要，本特性
  只读复用，经摘要/截断后进入领域知识字段。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 启用真实裁决的仿真 run 中，100% 的角色动作都有对应的裁决结果
  （叙事事件或失败记录），无静默丢失。
- **SC-002**: 真机验收场景（含至少一个风险动作）中，裁决产生至少一次非平凡的
  世界状态变更（效果落库），且裁决叙事与场景史料约束一致（人工核对）。
- **SC-003**: 裁决效果越界时，引擎拒绝并携带反馈重试，最终 run 正常结束——
  故障注入测试 100% 通过。
- **SC-004**: 裁决服务连续失败的场景下，仿真 run 完成率 100%（降级不中断）。
- **SC-005**: 离线测试套件零真实外部调用、全绿；既有 130 项离线测试无回归。

## Assumptions

- 大模型服务沿用项目既有出口与密钥环境变量（DeepSeek 系，模型选择属实现细节，
  不在本 spec 约束）。
- 裁决提示词的具体文本、模型参数、重试次数属实现细节，由 plan 阶段决定。
- 史料注入的检索方式（按世界/戏关联取最近或最相关原料）属实现细节；本特性
  不做语义排序等复杂检索，够用即可。
- 裁决频率与成本上限遵循宪章 VI 的成本边界：默认每个需裁决的动作一次调用，
  重试次数有硬上限。
- 多角色同 tick 并发裁决的并行化不做要求，串行即可（仿真规模小）。
