# Feature Specification: 统一 CLI 应用

**Feature Branch**: `018-cli-application`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: "将 narrative-sim 做成统一 CLI 应用。使用 argparse 提供 narrative 命令，支持服务启停与状态、资产调研、世界创建、仿真、事件导出和 MCP 启动；复用现有 Orchestrator，统一管理数据与日志路径，不改变现有业务契约。本特性不包含 CodeBuddy、GUI 和 PyInstaller 打包。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一个命令完成叙事工作流 (Priority: P1)

作为叙事仿真使用者，我希望从同一个命令入口完成资产调研、世界创建、仿真运行和事件导出，以便不必记忆多个脚本及其启动顺序。

**Why this priority**: 这是统一命令入口的核心价值，必须独立覆盖从输入到产物的完整工作流。

**Independent Test**: 使用离线角色后端创建一个世界、运行一次仿真并导出事件，无需启动外部服务即可验证；再单独验证真实调研命令能返回既有资产标识或新建资产标识。

**Acceptance Scenarios**:

1. **Given** 已配置的工作目录和可用资产， **When** 用户依次创建世界、运行离线仿真并导出事件， **Then** 每步都返回可供下一步使用的标识或路径，且导出内容与现有契约一致。
2. **Given** 一个调研主题和资产类型， **When** 用户执行调研命令， **Then** 系统沿用现有调研管线并返回资产标识，重复资产返回去重结果。
3. **Given** 缺少必要参数或引用不存在的对象， **When** 用户执行任一工作流命令， **Then** 系统给出可读错误并返回失败状态，不报告成功。

---

### User Story 2 - 可靠管理本地服务 (Priority: P2)

作为本地运行者，我希望用统一命令启动、检查、重启和停止所需服务，以便可靠地运行真实调研与仿真，并避免重复进程或误停其他程序。

**Why this priority**: 真实工作流依赖多个本地服务，服务状态不透明会阻塞主要使用场景。

**Independent Test**: 连续执行启动、重复启动、状态检查、重启和停止，验证服务就绪顺序、幂等性及进程归属保护，无需调用工作流命令。

**Acceptance Scenarios**:

1. **Given** 所需服务均未运行， **When** 用户启动应用， **Then** 系统按依赖顺序启动服务，并在全部必需服务就绪后报告成功。
2. **Given** 所需服务已健康运行， **When** 用户再次启动或查询状态， **Then** 启动不创建重复实例，状态准确区分运行、未运行和异常。
3. **Given** 某端口被非本应用进程占用， **When** 用户启动或停止服务， **Then** 系统不误停该进程，并给出明确错误。
4. **Given** 任一服务启动失败， **When** 启动命令结束， **Then** 系统报告失败及对应日志位置，不将部分就绪描述为整体成功。

---

### User Story 3 - 保持自动化与客户端兼容 (Priority: P3)

作为脚本作者或客户端维护者，我希望通过同一入口启动现有 MCP 服务，并获得稳定的命令输出和退出状态，以便将应用接入现有自动化流程。

**Why this priority**: 统一入口还应成为可编程接口，但不能破坏已有客户端和业务契约。

**Independent Test**: 启动 MCP 入口并由现有客户端完成一次工具调用；对其他命令验证成功与失败的退出状态及输出通道。

**Acceptance Scenarios**:

1. **Given** 现有 MCP 客户端配置， **When** 用户通过统一入口启动服务， **Then** 客户端可调用原有工具且工具行为不变。
2. **Given** 任一命令执行成功或失败， **When** 调用方检查退出状态与输出， **Then** 成功返回零状态，失败返回非零状态，结果与诊断信息分别输出。

### Edge Cases

- 服务已运行但不健康、端口被占用或运行状态文件过期时，命令必须识别异常而非盲目复用。
- 重复启动、重复停止及重启失败必须幂等，不留下重复服务或错误成功状态。
- 查询为空、资产类型无效、角色或场景缺失、运行标识不存在时，必须拒绝执行并说明原因。
- 用户中断仿真或服务启动时，已持久化的数据必须保持可恢复，命令不得误报完成。
- 配置、数据库或日志路径包含中文或空格时，命令行为必须一致。
- 密钥缺失时，仅相关真实能力失败；离线工作流和本地状态查询仍可使用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供单一命令入口，使用户能够发现全部可用命令、必要参数和使用示例。
- **FR-002**: 用户 MUST 能通过该入口启动、停止、重启和查询现有本地服务，启动 MUST 按依赖顺序等待必需服务就绪。
- **FR-003**: 服务管理 MUST 幂等，并 MUST 保护非本应用所有的进程，不得仅因端口匹配而停止未知进程。
- **FR-004**: 用户 MUST 能按主题和资产类型执行现有资产调研，并获得资产标识及是否去重的明确结果。
- **FR-005**: 用户 MUST 能创建世界，并使用现有角色后端、回合数、续跑、裁决和幕间记忆选项运行仿真。
- **FR-006**: 用户 MUST 能将指定运行的事件导出到目标路径，导出内容 MUST 继续满足现有事件契约。
- **FR-007**: 用户 MUST 能通过统一入口启动现有 MCP 服务，原有工具和客户端调用方式 MUST NOT 改变。
- **FR-008**: 所有命令 MUST 使用一致的配置、数据库、日志和运行状态位置；服务重启和命令切换 MUST NOT 改变所选数据集。
- **FR-009**: 配置解析 MUST 遵循“显式命令参数优先于环境配置，环境配置优先于默认值”，且 MUST NOT 在输出或日志中回显密钥。
- **FR-010**: 命令成功 MUST 返回零退出状态，失败 MUST 返回非零退出状态；结果与诊断信息 MUST 分别输出到标准结果和错误通道。
- **FR-011**: 命令失败 MUST 给出可读原因及可行的后续指引，默认 MUST NOT 向普通用户输出内部堆栈。
- **FR-012**: 新入口 MUST 复用现有业务流程，不得形成第二套资产、世界、仿真、导出或存储实现，现有离线回归基线 MUST 保持通过。

### Key Entities

- **命令执行结果**: 一次用户操作的成功状态、业务标识或产物路径、可读诊断及退出状态。
- **本地服务状态**: 服务名称、就绪状态、监听地址、进程归属和日志位置。
- **应用数据位置**: 用户选择的配置、数据库、日志与运行状态目录，在所有入口间保持一致。
- **工作流引用**: 资产、世界、运行和导出文件之间沿用现有标识与关系。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户仅查看命令内置帮助，即可在 5 分钟内完成一次离线世界创建、仿真和事件导出，产物通过现有契约检查。
- **SC-002**: 在验收环境中连续执行 3 轮启动、重复启动、状态检查、重启和停止，服务状态报告准确率为 100%，且不产生重复实例或误停外部进程。
- **SC-003**: 全部核心命令的成功与失败验收用例中，退出状态准确率为 100%，失败用例均包含可读原因，成功用例均包含所需业务标识或路径。
- **SC-004**: 同一数据集经命令入口和现有客户端交替操作后，资产、世界、运行与事件引用保持一致，重启后已提交数据保留率为 100%。
- **SC-005**: 现有离线自动化检查与最小链路全部通过，新入口的离线验收无需真实模型密钥即可完成。

## Assumptions

- 首个版本面向 Windows 本地单用户使用，保留现有开发脚本作为兼容入口。
- 真实调研和真实角色后端仍需要既有外部服务、模型配置及凭据；离线验收使用现有 Mock 能力。
- 嵌入模型及必要运行时由用户预先准备，本特性不负责模型下载或安装。
- 本特性统一现有配置和数据路径，但不主动迁移、删除或覆盖用户已有数据库。
- 不包含 CodeBuddy、图形界面、PyInstaller 打包、安装向导、自动更新或 Windows 系统服务。
- 资产、事件、世界状态等业务契约及现有 MCP 工具语义保持不变。
