# Feature Specification: Windows 独立应用

**Feature Branch**: `020-standalone-app`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: "将 narrative-sim 打包为 Windows 独立 CLI 应用。使用 PyInstaller onedir 产出 NarrativeSim.exe 和免安装 ZIP，支持现有 start/stop/restart/status、research、world create、run、export、mcp；包含 Python 运行依赖、必要数据资源与许可证，集成 LiteRT-LM 启动，模型文件作为可配置外部资源。程序资源与数据库、日志、密钥等用户数据分离。必须在没有 Python、uv 和原仓库目录依赖的干净 Windows 环境验证 Mock 链路、MCP 与服务管理。不包含 GUI、安装向导、自动更新、CodeBuddy 或自动模型下载器。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 无开发环境运行现有命令 (Priority: P1)

作为使用者，我希望解压应用后直接运行统一命令，不需要安装 Python、uv 或复制原项目源码，即可完成离线世界、仿真和事件导出。

**Why this priority**: 这是独立应用的核心交付价值，也是所有真实服务场景的基础。

**Independent Test**: 将发行目录复制到新的中文且含空格路径，只调用其中的可执行文件，完成帮助、离线建世界、4 回合仿真和事件导出。

**Acceptance Scenarios**:

1. **Given** 一台未准备项目开发环境的 Windows 机器， **When** 用户解压并运行应用命令， **Then** 不要求安装 Python/uv，且参数和结果与现有统一命令一致。
2. **Given** 全新用户数据目录， **When** 用户完成离线仿真并导出， **Then** 至少产生 5 条符合现有契约的事件，结果文件可由现有消费者读取。
3. **Given** 应用目录与原仓库位于不同位置， **When** 执行任一离线命令， **Then** 不读取原仓库的代码、数据库或配置。

---

### User Story 2 - 从发行目录管理完整技术栈 (Priority: P2)

作为本地运行者，我希望从同一可执行文件启动、检查和停止嵌入、调研及叙事服务，以便恢复真实工作流而不手工拼装多个运行环境。

**Why this priority**: 独立应用不仅要跑离线命令，还必须保持已有服务编排能力。

**Independent Test**: 用可控运行时验证发行版子进程启动参数与进程归属，再在具备真实资源的当前机器上完成一次服务健康检查和 MCP 调用。

**Acceptance Scenarios**:

1. **Given** 已配置的外部模型文件和可用运行时， **When** 用户启动技术栈， **Then** 三个服务按既有顺序就绪，且不调用开发环境可执行文件。
2. **Given** 模型或运行时缺失， **When** 用户启动服务， **Then** 错误明确指出需要配置的资源，离线命令仍可使用。
3. **Given** 发行版启动的 MCP 服务， **When** 现有客户端连接， **Then** 工具发现与调用行为不变，协议输出不受日志污染。

---

### User Story 3 - 安全升级和迁移用户数据 (Priority: P3)

作为已有数据的用户，我希望程序资源与用户数据分离，以便替换应用目录或移动数据时不会覆盖数据库、日志、配置和密钥。

**Why this priority**: 可升级性与数据安全决定发行版能否长期使用。

**Independent Test**: 准备包含三类数据库和配置的用户目录，替换程序目录后确认数据保持；检查发行包不含真实数据、密钥和缓存。

**Acceptance Scenarios**:

1. **Given** 默认首次启动， **When** 应用创建运行数据， **Then** 数据位于独立的用户数据目录而非程序资源目录。
2. **Given** 用户自定义数据库与配置路径， **When** 升级或移动程序目录， **Then** 这些路径与已有文件不被自动改写。
3. **Given** 发行包内容清单， **When** 用户检查许可证和资源， **Then** 能找到必要资源与上游许可证，且不存在真实数据库、密钥、虚拟环境或日志。

### Edge Cases

- 应用路径或数据路径包含中文、空格、长路径时，命令与子进程参数必须保持完整。
- 从任意当前目录调用可执行文件时，资源和默认数据路径不得依赖该当前目录。
- 发行版启动的子进程必须使用发行版自身，不得回退到 `python` 或 `uv`。
- stdio MCP 的标准输出必须只承载协议，第三方日志不得污染。
- 模型已导入但模型文件被移动时，可复用已导入模型；需要导入且文件缺失时必须明确失败。
- 升级程序目录不得自动迁移或删除旧数据库；异常退出后不得误停其他程序。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 发行版 MUST 提供单一 Windows 可执行入口，并支持现有全部统一命令及相同参数语义。
- **FR-002**: 发行目录 MUST 包含运行所需 Python 依赖、Schema、配置模板、组件资源和许可证，无需原源码目录。
- **FR-003**: 冻结后的资源定位和子进程启动 MUST 以发行目录或用户配置为准，MUST NOT 调用开发环境的 Python/uv。
- **FR-004**: 冻结后的默认用户数据目录 MUST 与程序目录分离；开发模式现有默认路径 MUST 保持兼容。
- **FR-005**: 用户配置、密钥、三类数据库、日志、导出与服务状态 MUST 位于用户数据位置或其显式路径，MUST NOT 打入发行包。
- **FR-006**: 发行版 MUST 支持配置的 LiteRT-LM 与模型文件，并保留模型检查、自动导入和服务健康检查能力。
- **FR-007**: 服务启停 MUST 继续执行进程所有权核验，发行版子进程 MUST 被正确识别为受管进程，且不得弹出额外终端窗口。
- **FR-008**: MCP stdio 与 HTTP 模式 MUST 保持既有协议和工具行为，CLI JSON 输出与诊断通道不得混杂。
- **FR-009**: 构建 MUST 产出包含单一顶层目录的免安装 ZIP，并附带使用说明、资源清单和许可证。
- **FR-010**: 构建过程 MUST 由统一脚本复现，记录应用版本及构建配置，且不读取或复制真实 `.env` 与数据库。
- **FR-011**: 现有资产、事件与世界契约 MUST NOT 改变；全部现有离线检查和最小链路 MUST 保持通过。
- **FR-012**: 文档 MUST 说明发行目录、用户数据目录、外部模型准备、真实服务配置及故障排查。

### Key Entities

- **发行目录**: 可执行文件、冻结运行依赖、只读资源与许可证组成的可移动目录。
- **用户数据目录**: 配置、密钥、数据库、日志、导出和服务状态的可写位置。
- **构建产物**: 版本化发行目录及对应的免安装压缩包。
- **冻结子进程**: 由发行版自身启动并受现有所有权规则管理的服务进程。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在新的中文且含空格目录中，仅使用发行目录可执行文件即可完成帮助、离线建世界、4 回合仿真和导出，至少 5 条事件全部通过现有契约。
- **SC-002**: 对发行版服务参数和进程树的检查中，100% 不调用系统 Python、uv 或原仓库文件；stdio 与 HTTP MCP 验收均通过。
- **SC-003**: 默认首次运行生成的全部用户可写文件均位于用户数据目录，替换程序目录后三类数据库与配置文件内容保持不变。
- **SC-004**: 发行包扫描未发现真实 `.env`、数据库、日志、模型、虚拟环境或缓存；必要资源和许可证检查通过率为 100%。
- **SC-005**: 全部现有离线自动化检查、构建复现和冻结应用验收通过，无已知命令行为回归。

## Assumptions

- 首个发行目标为 Windows 10/11 x64 单用户免安装应用。
- 默认冻结用户数据目录为当前用户的本地应用数据位置；开发模式仍默认项目根目录。
- 模型权重不随首版发行包提供，用户自行准备并配置；真实调研仍需要网络与凭据。
- 当前机器可代表干净验收环境，但必须只通过复制后的发行目录执行验收，不使用开发入口。
- 不包含 GUI、安装向导、自动更新、CodeBuddy、自动下载器或 Windows 系统服务。
