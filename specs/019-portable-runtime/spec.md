# Feature Specification: 可迁移运行时

**Feature Branch**: `019-portable-runtime`

**Created**: 2026-11-03

**Status**: Draft

**Input**: User description: "将 narrative-sim 改造成可迁移的 uv workspace 运行时。收拢本地维护的 WorldSeed 与 gptr-mcp，移除对固定本机绝对路径的依赖；统一 NARRATIVE_HOME、NARRATIVE_DB、LIBRARY_DB、CORPUS_DB 的数据目录规则；明确 LiteRT-LM 与嵌入模型的配置和启动方式。保证现有 CLI、MCP、调研、仿真及离线回归不回归。不包含 PyInstaller、GUI、CodeBuddy、模型权重入库或自动下载器。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在新位置获得可运行副本 (Priority: P1)

作为项目维护者，我希望只取得项目仓库就能在新目录或新电脑安装并运行现有功能，而不必重建原开发机的目录结构。

**Why this priority**: 当前本机路径和外部工作副本使项目无法可靠迁移，是独立应用交付的前置条件。

**Independent Test**: 将仓库复制到一个全新的中文且含空格目录，在不访问历史外部项目目录的情况下安装依赖，执行离线最小链路和统一命令入口。

**Acceptance Scenarios**:

1. **Given** 一份干净仓库副本和符合要求的基础运行环境， **When** 用户按文档安装依赖， **Then** 安装不依赖原开发机目录，命令入口可用。
2. **Given** 已完成安装的副本， **When** 用户运行离线仿真与事件导出， **Then** 结果满足既有契约且与迁移前行为一致。
3. **Given** 本地维护组件的来源与补丁记录， **When** 用户检查组件， **Then** 能追溯上游版本并找到相应许可证。

---

### User Story 2 - 统一迁移全部运行数据 (Priority: P2)

作为已有数据的用户，我希望通过一个数据根目录理解并迁移剧目库、调研主库、古籍库、日志和运行状态，同时仍能单独覆盖每个数据库位置。

**Why this priority**: 多库职责必须保持分离，但默认位置应一致，否则迁移时容易遗漏或写错数据。

**Independent Test**: 指定一个全新的数据根目录，分别执行调研、古籍检索、建世界和仿真，确认各数据写入预期位置；再逐个覆盖数据库路径验证优先级。

**Acceptance Scenarios**:

1. **Given** 用户指定数据根目录且未单独指定数据库， **When** 执行各类命令， **Then** 剧目库、调研主库和古籍库分别位于约定的独立默认位置，日志与运行状态也位于该根目录下。
2. **Given** 用户显式指定任一数据库位置， **When** 执行对应操作， **Then** 显式位置优先且不影响其他数据库。
3. **Given** 原位置已有数据库， **When** 用户改变数据根目录， **Then** 系统不会自动复制、移动、覆盖或删除旧数据。

---

### User Story 3 - 在新环境管理外部运行时 (Priority: P3)

作为本地运行者，我希望明确配置嵌入运行时、模型文件和调研服务所需资源，并获得可执行的缺失提示，以便在新环境恢复真实服务。

**Why this priority**: 真实服务需要非代码资源，只有代码可迁移还不能保证完整工作流可恢复。

**Independent Test**: 使用可控的伪运行时与模型文件验证路径解析、启动和错误提示；再以现有真实组件做一次兼容性检查，不在仓库中保存模型或凭据。

**Acceptance Scenarios**:

1. **Given** 用户已配置运行时和模型文件， **When** 启动技术栈， **Then** 服务按现有顺序启动并使用配置位置。
2. **Given** 运行时、模型文件或调研服务资源缺失， **When** 启动或检查服务， **Then** 系统指出缺失项及需配置的名称，不报告整体成功。
3. **Given** 用户未配置真实服务， **When** 运行离线工作流， **Then** 离线功能仍不依赖这些资源。

### Edge Cases

- 仓库或数据路径包含中文、空格或位于不同磁盘时，安装和运行行为必须一致。
- 原外部目录不存在、只有部分文件或版本不匹配时，不得回退到另一台机器的绝对路径。
- 数据库路径单独覆盖后，其他库仍必须保持原默认位置。
- 模型文件存在但尚未导入时，沿用现有导入流程；文件不存在时必须在启动前明确失败。
- 服务资源缺失不得影响离线 Mock 链路，也不得导致密钥写入仓库或日志。
- 已有数据库不随代码迁移自动复制，用户必须通过显式迁移步骤处理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目 MUST 在单一仓库中包含本地维护的世界引擎与调研服务代码，并记录上游来源、固定版本、本地修改和许可证。
- **FR-002**: 项目依赖与安装配置 MUST NOT 引用固定本机绝对路径，所有内部包 MUST 能由统一锁文件复现。
- **FR-003**: 用户 MUST 能在不含历史外部项目目录的新位置完成安装，并运行统一命令入口与离线最小链路。
- **FR-004**: 收拢组件 MUST NOT 改变现有适配器边界，外部库之间不得新增直接耦合或第二套存储入口。
- **FR-005**: 数据根目录 MUST 派生三个彼此独立的默认位置：剧目库、调研主库和古籍库；日志与服务运行状态 MUST 位于同一数据根目录下。
- **FR-006**: 每个数据库 MUST 能通过对应配置独立覆盖，显式数据库配置 MUST 优先于数据根目录派生值。
- **FR-007**: 改变数据根目录 MUST NOT 自动迁移或修改旧数据；文档 MUST 说明已有库的显式迁移方式。
- **FR-008**: 嵌入运行时、模型文件和调研服务资源位置 MUST 可由用户配置，运行代码 MUST NOT 依赖原开发机路径。
- **FR-009**: 服务启动 MUST 在资源缺失时给出具体缺失项和配置名称；部分资源可用 MUST NOT 被报告为整体就绪。
- **FR-010**: 模型已存在但未导入时 MUST 保留现有自动导入能力；模型权重、虚拟环境、日志和数据库 MUST NOT 被纳入版本控制。
- **FR-011**: 现有 CLI、MCP、调研、世界、仿真、导出及数据契约 MUST 保持既有语义，真实调研与仿真的凭据规则不变。
- **FR-012**: 安装、配置、迁移与故障排查文档 MUST 与实际行为一致，并包含新位置验收步骤。

### Key Entities

- **可迁移仓库**: 项目代码、本地维护组件、依赖锁定与来源许可证记录的集合。
- **数据根目录**: 派生三类数据库、日志和服务状态位置的统一配置。
- **数据库配置**: 剧目库、调研主库与古籍库各自的默认位置及独立覆盖值。
- **外部运行资源**: 嵌入运行时、模型文件及其显式配置，不属于版本控制内容。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在一个全新的中文且含空格目录中，用户不访问任何历史外部项目目录即可完成安装，并成功执行统一命令和离线最小链路。
- **SC-002**: 对运行清单、服务配置和运行代码执行固定本机路径扫描，未发现原开发机绝对路径；全部内部依赖均可从仓库与锁定配置复现。
- **SC-003**: 数据根目录与三个数据库独立覆盖的验收组合中，实际读写位置符合预期率为 100%，旧数据库内容保持不变的验证通过率为 100%。
- **SC-004**: 缺少运行时、模型或调研资源的逐项验收中，100% 返回包含缺失项和配置名称的失败信息，离线链路不受影响。
- **SC-005**: 现有全部离线自动化检查、MCP 契约检查和最小链路在迁移后通过，无已知行为回归。

## Assumptions

- 首个迁移目标仍为 Windows 本地单用户环境；基础 uv/Python 安装由用户准备。
- 本地维护组件允许在当前仓库中保存其源代码；上游历史通过版本标识记录，不要求保留完整提交历史。
- 模型权重、古籍原始藏书、数据库和凭据不属于仓库交付内容。
- 用户需要自行取得模型与嵌入运行时，本特性不提供下载器或许可证绕过。
- 不包含 PyInstaller、GUI、CodeBuddy、自动更新或安装向导。
