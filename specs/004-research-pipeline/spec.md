# Feature Specification: 自动资产调研管线

**Feature Branch**: `004-research-pipeline`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "M3 调研管线自动化：给一个人物/场景查询词，自动完成网络调研
（检索 + 深度抓取），结构化抽取为符合契约的资产 JSON 校验入库；资产带来源溯源；
入库前语义去重（复用 003 嵌入服务，可降级）；服务地址走环境变量；外部调研接入
封装在适配器内、离线 Mock 基线可测；M1/M2/003 不回归。（mydocs 手册 M3 节仅作参考）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查询词到入库资产 (Priority: P1)

给一个资产查询词（如"南宋临安城的酒楼"），系统自动完成网络调研，
把调研结果结构化为一份符合资产契约的资产，校验通过后入库，
资产携带来源溯源信息（来源链接非空、调研链有记录）。

**Why this priority**: 这是本特性的全部价值 —— 目前资产全靠手写 JSON，
调研自动化是后续 WorldSeed 组装（M4）的资产来源。

**Independent Test**: 以一个真实查询词运行调研管线，查询存储确认资产存在、
契约校验通过、溯源字段完整。

**Acceptance Scenarios**:

1. **Given** 调研服务与 LLM 可用，**When** 用人物类查询词运行调研管线，
   **Then** 库中新增一份契约校验通过的资产，其来源列表非空、
   溯源字段记录所用调研链
2. **Given** 调研返回的原始材料，**When** 结构化抽取结果不符合资产契约，
   **Then** 该资产被拒绝入库并给出明确失败原因，库中不留半成品

---

### User Story 2 - 入库前语义去重 (Priority: P2)

对含义相同的资产重复调研时，系统识别出"库中已有等价资产"，
不重复写入，而是返回已有资产的标识。

**Why this priority**: 资产库会被 M4/M5 反复消费，重复资产会污染
世界组装与检索；语义级去重（而非精确字符串匹配）才能拦住
"临安酒楼"与"南宋临安的酒家"这类同义查询。

**Independent Test**: 用两个措辞不同但含义相同的查询词先后调研，
确认库中只存在一份对应资产。

**Acceptance Scenarios**:

1. **Given** 库中已有某人物资产，**When** 用同义不同文的查询词再次调研同类资产，
   **Then** 判定为重复，返回已有资产标识，不产生新入库记录
2. **Given** 嵌入服务不可用，**When** 执行去重检查，
   **Then** 按降级策略处理（退化为名称精确匹配）并给出降级提示，不阻塞入库流程

---

### User Story 3 - 外部故障隔离与配置可移植 (Priority: P3)

检索/抓取等外部调研服务未启动或不可达时，管线明确报错并干净退出，
不影响仿真链路，库中不产生任何部分写入；换机器时只改环境变量即可
重定向调研服务。

**Why this priority**: 调研服务是外部常驻进程群，不能成为系统硬依赖；
宪章原则 VI 要求地址可重定向。

**Independent Test**: 停掉调研服务运行管线，验证报错明确、退出干净、
库内容不变；用环境变量指向 mock 端点验证重定向生效。

**Acceptance Scenarios**:

1. **Given** 调研服务不可达，**When** 运行调研管线，
   **Then** 在合理时限内明确报错，库中无任何新增记录
2. **Given** 未配置调研服务地址，**When** 启动调研管线，
   **Then** 明确提示缺少配置而非尝试连接默认地址

---

### Edge Cases

- 调研结果为空或材料不足以结构化：明确失败，不入库
- LLM 结构化抽取输出漂移（非 JSON / 缺字段）：被校验拦截，可重试，不穿透入库
- 查询词为空或仅空白字符：直接拒绝，不发起任何外部调用
- 同一资产并发/连续重复调研：去重判定生效，最多入库一份

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 接受查询词 + 资产类型，自动完成网络调研并产出
  符合资产契约的结构化资产
- **FR-002**: 入库资产 MUST 携带来源溯源：来源列表非空（含 URL），
  溯源字段记录实际使用的调研链
- **FR-003**: 资产 MUST 通过契约校验后才允许入库；校验失败 MUST 给出明确原因
  且不产生任何写入
- **FR-004**: 入库前 MUST 对名称与外观描述做语义级去重；判定重复时
  MUST 返回已有资产标识且不产生新写入
- **FR-005**: 语义去重 MUST 复用既有嵌入服务能力；嵌入服务不可用时
  MUST 降级为名称精确匹配并给出降级提示
- **FR-006**: 外部调研服务不可达时，管线 MUST 明确报错并干净退出，
  MUST NOT 留下部分写入，MUST NOT 影响仿真链路（M1/M2）
- **FR-007**: 调研服务地址与模型配置 MUST 从环境变量读取，MUST NOT 硬编码
  （宪章原则 VI）；未配置时 MUST 明确提示缺失而非连接默认地址
- **FR-008**: 外部调研服务的接入代码 MUST 封装在独立适配器内（宪章原则 II/IV），
  离线测试 MUST 能以 Mock 基线覆盖管线逻辑
- **FR-009**: 资产写入 MUST 只经 store.py 单一入口（宪章原则 III）；
  本特性 MUST NOT 改动资产/事件契约；M1、M2、003 既有验收 MUST 不回归

### Key Entities *(include if feature involves data)*

- **调研请求**：查询词、资产类型 —— 运行时输入，无持久化
- **调研来源**：URL、标题、内容摘要 —— 随资产溯源字段持久化
- **资产草稿**：调研材料经结构化抽取后的中间形态，契约校验通过才成为库中资产
- **溯源记录**：调研链标识、来源列表、调研时间 —— 资产契约 provenance 字段的填充来源

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 各用一个人物类与一个场景类真实查询词运行管线，各产出一份
  契约校验通过的入库资产，来源列表均 ≥ 1 条
- **SC-002**: 同义查询词重复调研时，库中对应资产数量为 1（去重生效）
- **SC-003**: 调研服务不可达时，管线在 60 秒内明确报错退出，库中零新增
- **SC-004**: M1 / M2 / 003 离线回归 100% 通过
- **SC-005**: 调研接入代码 100% 位于适配器模块内，仓库无硬编码调研服务地址

## Assumptions

- 检索、抓取、调研编排的具体技术选型（手册提及 SearXNG / GPT-Researcher /
  Crawl4AI，仅作参考）在 plan 阶段经研究确定，本规格不锁定；
  选中方案的安装与服务管理在仓库外，仓库只记录接入方式
- 结构化抽取沿用 002 的 DeepSeek 环境（LLM 密钥已在环境变量中）
- 语义去重复用 003 的嵌入服务与环境变量体系，降级语义与 003 一致
- 真机验收会产生少量 LLM token 成本与外部网络调用，属预期
- 本特性不做：资产人工审核界面、批量/定时调研调度、图像类资产的抓取与生成
