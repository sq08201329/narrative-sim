# Research: 古籍书目无损修复

## R1 文件名事实与解析边界

- **Decision**: 采用明确锚点规则，异常留空并出报告，不使用大模型。
- **Rationale**: 实测 13,409 份 TXT 文件名分为 1～6 段：三段 7,932、单段 2,989、
  四段 2,320、两段 142、五段 18、六段 8；另有连续连字符、卷数及“副本”。
  段数不能表达字段语义，唯一朝代锚点和目录丛书匹配才可作为可靠证据。
- **Alternatives considered**: 固定四段拆分（会重复当前错误）；大模型全库猜测
  （无来源事实且不可审计）；填满字段（违反用户要求）。

## R2 同名冲突与历史引用

- **Decision**: 未冲突及冲突组已存在的 ID 不变，恢复记录使用完整路径哈希后缀。
- **Rationale**: 修复 11 条覆盖记录，同时不使既有 `corpus:<book_id>` 调研引用失效。
- **Alternatives considered**: 全库重发 ID（破坏历史引用）；内容哈希去重（会丢掉
  不同目录的版本/来源记录）；再次按文件名覆盖（缺陷本身）。

## R3 安全迁移与性能

- **Decision**: SQLite 在线备份到新库，只更新 books 并补缺失书，校验后显式应用。
- **Rationale**: 既有 3,529,919 块无需重写；备份 API 比直接复制正在使用的文件安全，
  旧块可通过集合差校验逐字段保持不变。
- **Alternatives considered**: 全库重建（数小时索引成本）；直接改生产库（失败时
  回滚风险）；覆盖旧 `.bak`（破坏既有回滚点）。

## R4 原始事实与异常审计

- **Decision**: 继续以 `books.path` 保存完整原始路径、`content_hash` 保存规范化
  内容哈希；文件名由路径完整还原，不增加重复事实列。异常注记进入 `note` 和报告。
- **Rationale**: 满足来源可追溯并避免 Schema 冗余；所有结构化字段都可重新派生。
- **Alternatives considered**: 新增原始文件名列（与路径重复）；用正文推断作者
  （超出本特性可靠证据边界）。
